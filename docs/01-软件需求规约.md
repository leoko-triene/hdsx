# 软件需求规约

## 2026-07 功能增补

- 页面切换后保留课程选择、表单和课堂答疑上下文；答疑会话持久化并最多展示最近 30 条。
- 备课结果支持保存、下载、历史查看和主动删除；未保存记录按先进先出保留 30 条。
- 注册支持学生、教师和家长；家长注册必须绑定已有学生，并按学生隔离查看已发布报告。
- 教师可查看全部课程信息，但课程审批、备课、作业、答疑和学情操作仅限其负责课程。
- 作业可从知识库文件按章节生成课堂例题、练习题、思考题和拓展材料。
- 学生与教师均可查看薄弱知识画像和推荐材料；系统汇总提问与错题高频重点。
- 教师可从课程知识库自动生成知识点图谱，查看知识点与前置/相关/包含关系，并审核发布。
- 题目可关联一个或多个课程知识点；学生掌握度按知识点聚合，多次提交不重复计数。
- 教师可审核并修正 AI 答疑，系统通知学生；学生接收作业临近截止提醒。
- 作业材料生成应兼容模型代码块、顶层数组和常见字段别名；失败时进行一次受控 JSON 修复。
- 多选题支持任意选项组合，判断题固定提供正确/错误；题目在产生学生提交前允许再次编辑。
- 空标准答案由 AI 依据题目与课程知识库补充；学生提交后立即获得建议分、反馈和标准答案。
- 报告数组字段即使收到字符串也不得按字符渲染，应规范化为完整语句或条目。

## 1. 引言

### 1.1 目的

本文定义“AI 教育智能备课与个性化学习辅导智能体”的功能、接口、数据、安全和质量需求，是开发、测试和验收的共同依据。

### 1.2 项目范围

系统服务于教师、学生、家长和管理员，围绕课程知识库形成“资料入库—备课—答疑—作业—批改—学情—报告—知识图谱”的教学闭环。首版为 Vue Web 端和 FastAPI 后端，业务数据存入 MySQL，向量数据存入 Milvus，AI 能力由本地 Ollama 和重排序模型提供。

### 1.3 术语

- RAG：检索增强生成。
- 文档块：长文档经递归字符/token 分割得到的最小检索单元。
- 辅助评分：AI 给出建议分和依据，教师保留最终确认权。
- 掌握度：根据学生答题证据计算的 0～1 知识点指标。

## 2. 总体描述

### 2.1 用户角色

| 角色 | 权限边界 |
| --- | --- |
| 管理员 | 初始化用户、系统管理、查看运行状态 |
| 教师 | 管理本人课程、资料、备课、作业、批改和报告 |
| 学生 | 参与课程、提交本人作业、提问和查看本人学情 |
| 家长 | 仅查看已授权学生且已发布的报告 |

### 2.2 运行环境

- Windows 开发机；Python 使用 Conda `program-hd`，版本 3.11。
- MySQL 8.x，默认端口 3306。
- Milvus Docker 服务，默认端口 19530。
- Ollama，默认地址 `http://localhost:11434`。
- 模型：`qwen2.5:latest`、`embeddinggemma:latest`、`bge-reranker-v2-m3`。
- 后续部署目标为 Linux；嵌入式/TFLite 属于扩展验证。

### 2.3 约束

- 不得自动降级到 SQLite。
- 不得重复下载现有 Milvus 镜像或修改其已有数据目录。
- 模型不能执行自由 SQL；写操作必须通过后端业务服务。
- AI 评分与报告在发布前必须允许教师审核。

## 3. 功能需求

### FR-01 身份与权限

系统应支持初始化首个管理员、学生/教师/家长自主注册、登录、当前用户查询、资料修改、密码修改、管理员创建用户和基于角色的接口鉴权。家长注册必须绑定至少一个已有学生，管理员不得公开注册；修改密码必须验证当前密码。首个用户创建后初始化接口必须关闭。密码不得明文存储。

### FR-02 课程与知识结构

教师应能创建课程、章节和知识点。一个课程可设置多位负责人，任一负责人可维护课程、导入成员和审批申请。学生可发现课程并提交加入理由，只有审批通过或由负责人导入后才成为课程成员。教师只能操作自己负责的课程；管理员可管理全部课程。课程应支持学科、学段、描述和状态。

系统应支持从课程知识库文档自动抽取知识点和关系，生成课程级知识图谱；教师可审核后发布，未审核状态为 draft。图谱应支持可视化展示和版本管理，重新生成时创建新版本而不是覆盖旧版本。

### FR-02A 课程学生管理

课程负责人应能上传 CSV 批量导入学生，表头包含 `username`、`display_name`，可选 `email`、`password`；已有学生账号直接加入课程，新账号按名单创建。系统应展示逐行导入结果。学生可以申请加入课程，负责人可以同意或拒绝并填写审批意见。

### FR-03 文档知识库

系统应支持一次选择最多 20 个 TXT、Markdown、PDF、DOCX 文件批量上传。上传时验证文件大小、文件名和内容 SHA-256；同一课程中内容相同的文件即使改名也必须阻止入库，并由 MySQL 唯一约束抵抗并发重复。知识库页面应展示文件名、分类、状态、分块数和上传时间。文档使用递归分割，默认约 650 token、重叠 100 token。每块必须包含 `source`、`filename`、`chunk_index`、`category` 和 `course_id`。

系统通过 MySQL 关键词检索和 Milvus 向量检索执行多路召回，以 RRF 合并去重，再用 BGE 重排序并返回来源。当前版本已完成完整检索链路并通过真实服务验证。

### FR-04 智能备课

教师输入课程、章节或主题、授课对象、课时、资源类型和要求后，系统应检索课程资料并生成可直接阅读的 Markdown 文本。历史标题必须使用用户填写的章节或主题。收藏操作只改变状态，独立收藏夹入口负责页面跳转；历史的预览、收藏、下载和删除操作在桌面端等宽单行排列。

备课不得在主题不匹配时直接使用课程最近上传的资料。系统应优先整句命中，再使用向量、关键词和 BGE 重排序；没有达到相关性门槛时返回证据不足。作业材料生成支持同时选择 1～10 份同课程 ready 文件，并保证不同文件都有机会进入上下文。

### FR-05 作业与批改

教师应能创建作业、添加客观题或主观题并发布，并按课程查看作业列表、详情、提交数量和学生提交队列。题目可关联课程知识点，用于后续掌握度分析。学生应看到所有对其发布的作业、课程、标题、总分、题目数、截止时间和个人提交状态，并能进入单个作业填写。学生接口不得返回标准答案或 rubric。客观题采用确定性规则判分；主观题依据标准答案和 rubric 调用模型辅助评分。每项结果包含分数、置信度、评语和评分依据，默认处于待复核状态。

学生只能读取已正式加入课程的知识库、作业和答疑能力；仅发现课程或提交待审批申请不授予数据读取权限。课堂答疑必须以课程名称选择器展示学生已加入或教师负责的课程，不要求用户输入内部课程编号。

### FR-05A 角色化界面

系统导航、总览快捷入口、页面和操作按钮必须根据 admin、teacher、student、parent 角色显示。教师可创建课程、上传资料、创建与批改作业；学生只能查看参与课程、检索资料、填写作业和查看本人学情；家长只查看已授权且已发布的报告。后端必须独立执行同样的权限校验，不能只依赖前端隐藏按钮。

导航顶部应明确显示当前位置，退出登录入口固定在窗口右上方；详情页返回按钮应具有明显的视觉层级。

### FR-06A 知识点掌握度

系统应根据学生提交和教师复核结果，按知识点计算掌握度。同一作业的多次提交只取最新有效结果，不得重复计数。学生可查看本人各课程知识点的掌握度、薄弱项和推荐学习路径；教师可查看其负责课程中已加入学生的掌握度。家长仅可查看已绑定学生的掌握度。

### FR-06 教师复核

教师可调整最终得分和评语。最终得分不得超出题目满分。系统保留 AI 建议与最终结果，成绩发布前完成复核。

### FR-07 课程答疑

学生创建课程问答会话后可提问。系统优先依据课程知识库回答；课程证据少于两个片段时，可检索并抓取最多两篇公开学习网页作为临时补充。课程与网页引用都必须可追溯，网页不得自动入库；两类证据均为空时应拒绝编造并标记需要教师处理。

### FR-08 学情分析

系统按学生和知识点保存掌握度、等级、证据数量与算法版本。默认等级为薄弱（<0.60）、待巩固（0.60～0.79）、已掌握（>=0.80）。学生只能查看本人数据。

### FR-09 学习报告

教师选择学生、课程和周期生成周报或月报。指标必须先由数据库计算，LLM 只负责自然语言解释。生成结果为待审核状态，未发布报告家长不可见。

### FR-10 健康与错误

系统应提供存活与就绪检查。MySQL、Ollama 等依赖不可用时，就绪接口返回 503 和依赖错误。业务错误统一返回 `code`、`message`、`details` 和 `request_id`。

### FR-11 Agent、Skill、Prompt、Tool 与 MCP

每个 AI 能力必须绑定有语义版本号的 Skill 和 Prompt，声明输入、输出、允许工具及输出模式。Tool 必须通过白名单注册、执行参数校验并复用业务权限，模型不得执行自由 SQL。所有 Agent 返回 trace_id 和调用元数据。内部 MCP 网关仅向管理员开放注册工具，远端 MCP 默认关闭；启用时必须同时配置显式主机白名单。管理员界面应能检查当前实际注册的 Skill、Prompt、Tool 与 MCP 状态。

### FR-12 网络资料获取与确认入库

课程负责人应能按关键词搜索公开学习页面或直接输入 HTTP/HTTPS URL。系统必须先展示标题、最终 URL、正文长度和正文预览，不得自动写入课程知识库；只有用户点击确认后才能创建文档、分块和向量索引。用户可拒绝草稿，未处理草稿默认 24 小时过期。确认文档必须保留来源 URL 和抓取时间，并按正文内容 SHA-256 去重。

抓取器只允许公开 HTTP/HTTPS、80/443 端口和文本页面，限制响应体及正文长度，并在初始地址及每次重定向前阻止本机、内网、链路本地、组播及保留地址。网页内的提示词或命令只能作为不可信知识正文，不能改变 Agent 系统指令。MCP 可以创建预览，但不得提供确认入库 Tool。

## 4. 非功能需求

### NFR-01 安全

密码使用 PBKDF2-HMAC-SHA256 与随机盐；JWT 使用 HMAC 签名并设置到期时间。文件路径必须去除目录部分。日志不得记录密码、令牌和完整学生隐私。

### NFR-02 性能

普通 CRUD 在本地网络目标响应时间小于 1 秒；单次普通检索目标小于 3 秒；模型生成允许 120 秒超时。长任务应逐步迁移到异步队列。

### NFR-03 可靠性

数据库事务失败必须回滚。模型输出必须经过 JSON 和范围校验。外部服务故障不得产生伪造成功结果。

### NFR-04 可维护性

依赖方向为 API → Service → Repository/ORM。配置来自环境变量。数据库变更使用 Alembic。所有模块具有自动化测试或明确验收用例。

### NFR-05 可追溯性

AI 回答保存 `trace_id`、引用、置信度和模型配置；重要业务写操作应记录审计日志。

## 5. 验收标准

使用固定演示课程完成以下流程：初始化账号、教师创建课程、上传教材并检索、生成教案、创建和发布作业、学生提交、AI 批改、教师复核、查询学情、生成待审核报告。自动化测试通过，接口文档可访问，依赖异常有明确提示。

## 6. 增量需求（2026-07-14）

系统必须支持作业多次提交、指定知识文档删除、作业删除、课程必填信息及后续修改/删除。作业、课堂运营、学情分析和教师报告必须先选择课程再进入详情。所有要求模型返回结构化数据的接口必须经过 Schema 与 Pydantic 校验，并在格式异常时生成可复核的合法兜底结果。备课内容必须支持收藏页与历史操作；桌面端左侧任务栏保持固定。

### FR-PLUGIN-01 源码组合模块与交互

系统应允许可信协作者在根目录 `plugins/<模块>/` 提供算法或服务适配，由 `integrations` 稳定适配层组合进原有业务，不提供运行时插件选择。`plugins/spider` 同时服务知识库受控入库和答疑只读网络补充。知识库课程选择应横向滚动并高亮，主体按“左侧上传/爬虫、右侧检索/文件”布局。
# 本轮需求增补（2026-07-14）

- FR-KB-PREVIEW：已加入课程的用户可以预览知识库文档解析内容；Markdown/网页正文应渲染，其他格式按纯文本显示，预览不得绕过课程可见权限。
- FR-MODEL-ADMIN：仅管理员可以查询、测试和修改 LLM/Embedding Provider；支持 Ollama 与 OpenAI 兼容 API，LLM 与 Embedding 可独立配置。
- SEC-MODEL-KEY：模型 API Key 不得明文返回或进入 Git，应使用应用密钥加密持久化；教师、学生和家长不得访问模型配置接口或页面。
- NFR-VECTOR-COMPAT：实际 Embedding 维度必须通过测试，Milvus collection 维度不一致时必须明确拒绝写入。
# 2026-07-14 课程导航与学情需求增补

- 课程中心与课程选择页桌面端每行最多显示 3 个课程，按钮、徽标和状态文字不得换行。
- 作业中心、课堂运营、学情分析和学习报告必须按路由课程 ID 直接加载，顶部显示固定课程名称和返回按钮；不同课程页面状态不得串用。
- 课程中心进入知识库必须默认选中所点击课程；智能备课收藏夹面包屑应支持返回智能备课。
- 知识检索必须过滤负相关、过短和单一来源过多的结果。
- 学生课程学情必须覆盖全部已发布作业的完成与未完成情况、得分表现和课堂答疑参与/风险信息。
