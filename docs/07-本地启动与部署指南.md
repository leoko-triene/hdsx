# 本地启动与部署指南

本文档说明如何把项目从源码启动到可访问状态。示例命令以 PowerShell 为准，其他 shell 请自行调整路径分隔符。

> 下文用 `<project_root>` 表示项目根目录（包含 `backend/`、`frontend/`、`scripts/` 的目录）。

---

## 一、依赖清单

| 环境/服务 | 版本/说明 | 用途 |
|-----------|-----------|------|
| Python | 3.11+（推荐在 Conda 虚拟环境中运行） | 后端运行环境 |
| MySQL | 8.0+，可用 Docker 部署 | 业务数据库 |
| Milvus | 2.3+，可用 Docker Compose 部署 | 向量召回 |
| 模型服务 | **Ollama 本地服务** 或 **兼容 OpenAI API 的在线服务** | LLM / Embedding |
| BGE Reranker | 本地模型目录路径 | 重排序 |
| Node.js | 24 LTS 或更高 | 前端构建 |
| pnpm | 9+ | 前端包管理 |

> 模型服务支持 `ollama` 和 `openai_compatible` 两种 provider。`openai_compatible` 可覆盖 OpenAI、DeepSeek、阿里云百炼、智谱 AI 等。

---

## 二、首次部署步骤

### 1. 复制环境变量

```powershell
cd <project_root>
copy .env.example .env
```

然后编辑 `.env`，重点配置：

- `MYSQL_PASSWORD`：与创建 MySQL 容器时一致。
- `RERANKER_MODEL_PATH`：指向本地 `bge-reranker-v2-m3` 目录。
- `LLM_*` / `EMBEDDING_*`：选择并填写模型服务 provider，详见[模型服务配置](#三模型服务配置)。

### 2. 启动 MySQL

若使用 Docker（首次）：

```powershell
docker run -d `
  --name edu-mysql `
  -p 3306:3306 `
  -e MYSQL_ROOT_PASSWORD=root_change_me `
  -e MYSQL_DATABASE=ai_education `
  -e MYSQL_USER=ai_education_app `
  -e MYSQL_PASSWORD=change_me `
  -v "<mysql_data_dir>:/var/lib/mysql" `
  mysql:8.4 `
  --character-set-server=utf8mb4 `
  --collation-server=utf8mb4_0900_ai_ci
```

后续重启：

```powershell
docker start edu-mysql
```

> `<mysql_data_dir>` 替换为本地持久化目录，例如 `D:\Docker\mysql` 或 `./data/mysql`。

### 3. 启动 Milvus

若使用 Docker Compose，参考 Milvus 官方文档启动 `etcd`、`minio`、`standalone` 三个服务。日常重启：

```powershell
docker start milvus-etcd milvus-minio milvus-standalone
```

等待 10~20 秒让 Milvus 初始化完成。

### 4. 安装 Python 依赖

```powershell
conda activate llm_learn
cd <project_root>
pip install -r requirements.txt
```

若还没有 `requirements.txt`，可手动安装核心依赖：

```powershell
pip install fastapi uvicorn[standard] sqlalchemy alembic pydantic pydantic-settings pymysql python-multipart httpx pymilvus pytest pytest-asyncio ruff
```

### 5. 执行数据库迁移

```powershell
cd <project_root>\backend
alembic upgrade head
```

### 6. 安装前端依赖

```powershell
cd <project_root>\frontend
pnpm install
```

### 7. 启动后端

```powershell
cd <project_root>
powershell -ExecutionPolicy Bypass -File .\start_backend.ps1
```

或手动：

```powershell
cd <project_root>\backend
python -m uvicorn app.main:app --reload --app-dir .
```

### 8. 启动前端

```powershell
cd <project_root>
powershell -ExecutionPolicy Bypass -File .\start_frontend.ps1
```

或手动：

```powershell
cd <project_root>\frontend
pnpm exec vite --host 127.0.0.1
```

> Windows 上 Vite 可能默认监听 IPv6（`::1`），导致 `127.0.0.1` 访问不到，加 `--host 127.0.0.1` 可强制 IPv4。

## 三、模型服务配置

项目通过 `LLM_PROVIDER` 和 `EMBEDDING_PROVIDER` 切换模型服务，`.env.example` 中已给出多组示例，取消对应注释即可。

### 通用配置项

```ini
LLM_PROVIDER=ollama                    # ollama | openai_compatible
LLM_BASE_URL=http://localhost:11434
LLM_API_KEY=                           # 在线服务必填
LLM_MODEL=qwen2.5:latest

EMBEDDING_PROVIDER=ollama
EMBEDDING_BASE_URL=http://localhost:11434
EMBEDDING_API_KEY=
EMBEDDING_MODEL=embeddinggemma:latest
EMBEDDING_DIMENSION=768
```

### 方案 A：本地 Ollama（默认）

1. 安装并启动 Ollama：`https://ollama.com`
2. 拉取模型：

```powershell
ollama pull qwen2.5:latest
ollama pull embeddinggemma:latest
```

3. `.env` 使用默认配置即可。

### 方案 B：DeepSeek

```ini
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=your-deepseek-api-key
LLM_MODEL=deepseek-chat
```

> DeepSeek 目前以 LLM 为主，若需同时用于 Embedding，请确认所用模型支持 `/embeddings`。

### 方案 C：OpenAI

```ini
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=your-openai-api-key
LLM_MODEL=gpt-4o-mini

EMBEDDING_PROVIDER=openai_compatible
EMBEDDING_BASE_URL=https://api.openai.com/v1
EMBEDDING_API_KEY=your-openai-api-key
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSION=1536
```

### 方案 D：阿里云百炼（DashScope）

```ini
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_API_KEY=your-dashscope-api-key
LLM_MODEL=qwen-max

EMBEDDING_PROVIDER=openai_compatible
EMBEDDING_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
EMBEDDING_API_KEY=your-dashscope-api-key
EMBEDDING_MODEL=text-embedding-v3
EMBEDDING_DIMENSION=1024
```

### 方案 E：智谱 AI

```ini
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_API_KEY=your-zhipu-api-key
LLM_MODEL=glm-4-flash

EMBEDDING_PROVIDER=openai_compatible
EMBEDDING_BASE_URL=https://open.bigmodel.cn/api/paas/v4
EMBEDDING_API_KEY=your-zhipu-api-key
EMBEDDING_MODEL=embedding-3
EMBEDDING_DIMENSION=2048
```

### 注意事项

- **Embedding 维度必须一致**：`EMBEDDING_DIMENSION` 要与所选 embedding 模型实际维度一致，且 Milvus collection 的维度也要匹配。若切换了 embedding 模型，通常需要重新创建 Milvus collection 或重新入库文档。
- **JSON mode 行为差异**：不同厂商对 `response_format: {"type": "json_object"}` 的支持程度不同。若出现 JSON 解析失败，可尝试换用更明确支持 JSON 输出的模型（如 qwen-max、glm-4、gpt-4o 等）。
- **旧配置兼容**：若 `.env` 只配置了旧的 `OLLAMA_*` 字段，系统会自动回退到 Ollama provider。

## 四、验证是否跑通

1. 后端健康检查：

```powershell
Invoke-WebRequest -Uri "http://127.0.0.1:8000/health/ready" -TimeoutSec 10
```

应返回 `200`，且 `mysql`、`llm`、`embedding`、`milvus` 均为 `{"ok": true}`。

2. 前端页面：

浏览器打开 `http://127.0.0.1:5173`

3. 后端 API 文档：

`http://127.0.0.1:8000/docs`

4. 创建首个管理员（仅当数据库为空时可执行一次）：

```powershell
$body = @{ username="admin"; email="admin@example.com"; display_name="Admin"; password="admin123"; role="admin" } | ConvertTo-Json
Invoke-WebRequest -Uri "http://127.0.0.1:8000/api/v1/auth/bootstrap" -Method POST -Body $body -ContentType "application/json"
```

## 五、日常重启命令

```powershell
# 1. 启动 Docker 服务
docker start edu-mysql milvus-etcd milvus-minio milvus-standalone

# 2. 激活 Python 环境
conda activate llm_learn

# 3. 启动后端（终端 A）
cd <project_root>
powershell -ExecutionPolicy Bypass -File .\start_backend.ps1

# 4. 启动前端（终端 B）
cd <project_root>
powershell -ExecutionPolicy Bypass -File .\start_frontend.ps1
```

cd <project_root>

## 七、常见问题

### 1. Docker Hub 拉取镜像失败

在 Docker Desktop 设置中添加国内镜像源，例如清华镜像：

```json
{
  "registry-mirrors": ["https://mirrors.tuna.tsinghua.edu.cn"]
}
```

然后重启 Docker Desktop。

### 2. `alembic upgrade head` 报 `Duplicate column name`

后续迁移脚本已做幂等处理，直接重新执行即可：

```powershell
alembic upgrade head
```

### 3. 前端 `pnpm install` 提示 esbuild 构建脚本被忽略

确保 `frontend/pnpm-workspace.yaml` 包含：

```yaml
packages:
  - "."

onlyBuiltDependencies:
  - esbuild
```

然后重新 `pnpm install`。

### 4. 前端能启动但 `127.0.0.1:5173` 访问不了

Vite 可能监听在 IPv6 的 `::1`。启动时加 `--host 127.0.0.1`：

```powershell
pnpm exec vite --host 127.0.0.1
```

### 5. `/health/ready` 返回 503

查看 `checks` 中哪个服务失败：

- **mysql**：检查 MySQL 容器是否启动、`.env` 账号密码是否正确。
- **llm / embedding**：检查对应 provider 的地址、API Key、模型名是否配置正确；Ollama 需确认模型已拉取。
- **milvus**：检查三个 Milvus 容器是否都启动并初始化完成。

### 6. 切换模型后向量检索异常

Embedding 模型变更后，旧文档的向量维度与新查询不一致。解决：

1. 清空 Milvus collection 中的旧数据（或删除后重建 collection）。
2. 在项目里重新上传/入库文档。

### 7. 智能备课导出 Word/PPT 失败

- 确保已安装 `python-docx` 和 `python-pptx`：

```powershell
pip install python-docx python-pptx
```

- `lesson_plan`/`lecture`/`exercise` 仅支持导出 `docx`。
- `ppt_outline` 仅支持导出 `pptx`。
- 导出文件保存在 `storage/exports/{course_id}/`，数据库会记录到 `generated_documents` 表。
- 若下载到的 `.pptx`/`.docx` 只有 1 KB 左右，说明拿到的是 JSON 元数据而非文件流；当前 `POST /lesson-resources/{id}/export` 已直接返回文件流。

### 8. 模型输出 JSON 解析失败

- 优先使用明确支持 JSON mode 的模型（如 qwen-max、glm-4、gpt-4o）。
- 检查 `.env` 中 `LLM_MODEL` 是否正确。
- 在 `.env` 中切换 `LLM_PROVIDER` 后需要重启后端。
