# 用户使用手册

## 2026-07 新功能入口

- 教师：在“智能备课”保存或下载历史；在“作业中心”选择知识库文件生成章节材料，并在编辑题目时关联知识点；在“课堂运营”查看高频问题并修正 AI 回答；在“知识点图谱”生成、查看和审核课程知识图谱。
- 学生：在“学情分析”查看薄弱知识画像与推荐内容；在“我的知识点掌握度”查看按课程的知识点掌握情况；在“通知中心”查看截止提醒和教师修正消息。
- 家长：注册时填写一个或多个已有学生用户名，登录后在“学习报告”顶部切换孩子；只能看到对应孩子已发布的报告。
- 所有角色：切换页面不会清空当前操作状态；课堂答疑左侧可恢复最近对话，通知点击后会标记已读并跳转到相关功能。
- 教师在作业详情中可点击每道题后的“修改题目”；已有学生提交后系统会锁定题目，避免改变批改依据。
- 单选、多选和判断题可直接点选标准答案；简答与论述题允许留空，由 AI 结合课程知识库补充，之后仍可修改。
- 学生点击“提交并立即批改”后会直接看到建议得分、批改反馈与标准答案；主观题仍以教师最终复核为准。

## 1. 系统准备

管理员需要 Docker Desktop、已有 Milvus 服务和 Ollama。项目 MySQL 使用 `edu-mysql` 容器，持久化目录为 `D:\Docker\mysql`。Python 必须使用 `program-hd`。确认 Ollama 已有 `qwen2.5:latest` 和 `embeddinggemma:latest`。

执行环境检查：

```powershell
conda activate program-hd
cd D:\class\Season4_5\hdsx-d\Code1
python scripts\check_environment.py
```

## 2. 初始化与启动

1. 启动 Docker Desktop，确认 `edu-mysql`、`milvus-standalone`、`milvus-etcd`、`milvus-minio` 正常；首次自行部署 MySQL 时再执行 `database/init_mysql.sql`。
2. 在 `backend` 目录运行 `alembic upgrade head`。
3. 可运行 `python scripts/seed_demo.py` 创建演示数据。
4. 从 `Code1` 启动后端：

```powershell
powershell -ExecutionPolicy Bypass -File .\start_backend.ps1
```

5. 安装前端依赖并启动：

```powershell
powershell -ExecutionPolicy Bypass -File .\start_frontend.ps1
```

后端手动命令必须包含 `--reload-dir backend`，否则 Uvicorn 会递归扫描 `frontend/node_modules`：

```powershell
uvicorn app.main:app --reload --reload-dir backend --app-dir backend
```

浏览器打开 `http://127.0.0.1:5173`。API 文档位于 `http://127.0.0.1:8000/docs`。

项目内已提供便携 Node.js 和 pnpm，普通终端中没有全局 `node/npm/pnpm` 不影响启动。可以使用 `.\bin\node.cmd --version` 和 `.\bin\pnpm.cmd --version` 验证。请勿执行全局 pnpm 安装。

## 3. 首次管理员

若不使用演示脚本，可在 Swagger 中调用 `POST /api/v1/auth/bootstrap` 创建首个管理员。只允许空系统调用一次。随后通过登录接口获取令牌。

演示脚本账号为 admin、teacher、student、parent，统一初始密码 `Demo123!`。只用于本地演示，正式使用必须立即修改。

登录页提供“注册账号”。注册时可以选择学生、教师或家长身份，填写用户名、姓名、可选邮箱和至少 8 位密码；家长必须绑定至少一个已存在的学生用户名。管理员账号仍不能通过公开注册创建。登录后所有角色可进入“账号设置”修改姓名、邮箱和密码。

## 4. 教师操作

### 4.1 创建课程

登录教师账号，进入“课程”，填写课程名称、学科、学段和描述。创建者自动成为第一位负责人。在“成员与负责人”中可添加其他教师为共同负责人、审批学生申请，并查看已加入学生。

批量导入使用 CSV，示例：

```csv
username,display_name,email,password
20260001,张三,zhangsan@example.com,
20260002,李四,lisi@example.com,CustomPass123!
```

未填写每行密码时使用页面统一初始密码。导入后应通知学生首次登录修改密码。

### 4.2 上传教材

进入“知识库”后，在标题说明下方横向滑动课程标签，点击后高亮当前知识库。桌面端左侧上方上传文件、下方抓取网页；右侧上方检索知识、下方查看文件。一次可选择最多 20 个 TXT、MD、PDF、DOCX 文件，系统按内容 SHA-256 判断重复。

### 4.2A 从网页导入资料

课程负责人在左侧“从网络获取学习资料”中输入主题或 HTTP/HTTPS 地址。实际爬虫位于 `plugins/spider`。点击“抓取并预览”只创建临时草稿；核对来源与渲染后的 Markdown 后，点击“确认并写入知识库”才会建立索引，也可直接删除抓取记录。

草稿需在 24 小时内确认。网页要求登录、依赖 JavaScript、正文过短、响应超过 2MB、使用非 80/443 端口或地址指向内网时，系统会拒绝。不要尝试绕过付费墙、登录或网站使用条款。确认后的网页资料会参与后续 AI 功能，因此确认前必须检查准确性。

### 4.3 智能备课

进入“智能备课”，填写的章节或主题会直接成为历史标题。右侧历史的预览、收藏、下载、删除在桌面端等宽单行排列；点击收藏只切换星标，不会跳转。使用页面上方独立的“★ 收藏夹”按钮进入收藏页面。若显示知识库证据不足，应先上传对应教材。

章节或主题应与所选课程资料一致。系统不会再使用无关的最近文件强行生成；若主题与知识库无关，会提示检查课程、主题或上传对应教材。教师在作业的“AI 从知识库生成材料”区域可勾选多份参考资料，最多 10 份，至少选择 1 份。

所有业务页面顶部显示“工作台 › 当前功能”，右上角固定显示账号与“退出登录”。作业详情中的“返回作业列表”使用浅蓝色醒目按钮。

### 4.4 作业与批改

进入“作业中心”可查看作业卡片、课程、状态、总分、题目数和提交数。点击“创建作业”建立草稿，进入详情后逐题添加并发布。在题目编辑区可为每道题勾选关联的知识点；这会影响学生掌握度的计算。学生提交后，右侧提交队列显示学生姓名和状态；打开提交后启动 AI 辅助批改，再逐题确认最终分数和评语。

主观题必须填写 rubric。AI 分数只是建议，教师需要核对标准答案、评分点和证据。

### 4.5 知识点图谱

教师进入左侧“知识点图谱”，先选择课程。若该课程尚未生成图谱，可点击“从教材生成知识点图谱”，系统会从课程知识库的 ready 文档中抽取知识点和关系，生成 draft 版本。审核通过后状态变为 approved。图谱以 ECharts 力导向图展示，下方列出知识点和关系。

除 AI 生成外，课程负责人/管理员还可在图谱页面手动维护：点击“添加知识点”创建新节点，点击知识点右侧“编辑/删除”修改或删除节点；点击“添加关系”连接两个知识点，点击关系右侧“编辑/删除”修改或删除边。手动编辑会自动同步到最新图谱版本，不会额外创建新版本。

重新生成会创建新版本，旧版本保留。生成失败（如模型返回空结果）不会创建空图谱，页面会提示错误。

### 4.5 学情与报告

“学情分析”按学生 ID 查询掌握度，并可生成个性化学习路径。报告页面填写学生、课程和周期，生成结果默认为待审核；教师审核发布后才可作为正式家校通知。

## 5. 学生操作

学生界面不会显示课程创建、文件上传、智能备课、知识点图谱生成、报告生成等教师功能。学生在课程页可发现课程并申请加入；负责人批准前不能读取该课程知识库、作业或答疑。批准后课程进入“已加入课程”。作业中心按课程分组，课堂答疑使用课程名称下拉框；标准答案不会在学生接口或页面中返回。

学生可在“我的知识点掌握度”中选择已加入课程，查看各知识点的掌握度、薄弱项和推荐学习路径。数据来自教师复核或批改后的 `MasterySnapshot`，多次提交不会重复计数。

```json
{"answers":[{"question_id":1,"answer":"A"},{"question_id":2,"answer":"解释内容"}]}
```

学生只能查看本人的学情信息，不能修改 AI 或教师评分。

## 6. 家长操作

家长只能查看已建立亲子授权关系且经教师审核发布的报告。管理员通过家长学生授权接口建立关系，家长通过 `/api/v1/parent/reports` 查看报告。

## 7. 常见问题

### 管理员检查 Agent 能力

管理员登录后进入“Agent 能力”，可查看当前启用的 Skill/Prompt 版本、输入变量、允许工具和 MCP 方法。该页面用于发布前核对，不允许在线修改 Prompt。内部 MCP 接口为 `POST /api/v1/mcp`，必须使用管理员 Bearer Token；远端 MCP 默认关闭，普通用户不需要配置。

### 后端返回 MySQL 连接失败

检查 MySQL 是否启动、端口是否为 3306、数据库和应用账号是否已创建、`.env` 密码是否一致。系统不会改用 SQLite。

### Ollama 调用失败

访问 `http://localhost:11434/api/tags`，确认服务运行且模型名称与 `.env` 相同。8GB 显存环境避免同时运行多个生成任务。

### Milvus 连接失败

检查现有 Docker 服务和 19530 端口。不要重新下载镜像或创建新的 yml；记录容器错误后再处理。

### PDF/DOCX 无法解析

确认不是扫描图片型 PDF、文件未加密且内容非空。扫描件需要后续 OCR 支持。

### 回答没有引用

系统会先查课程知识库，证据不足时尝试补充最多两篇公开网页。回答下方“课程资料”或“网络补充”可查看来源；两类引用都没有时，说明检索和网络补充均未取得依据，应调整问题、补充教材或转教师。

### 网页搜索结果不准确或搜索暂时失败

搜索功能依赖公开搜索页面，结果可能变化。可以复制可信教程或官方文档的 URL，使用“直接粘贴网页地址”抓取。若页面需要登录或 JavaScript 渲染，应改用作者提供的 PDF/Markdown 并走本地文件上传，不要绕过访问限制。

## 8. 停止与维护

使用终端 Ctrl+C 停止前后端。数据库升级前先备份 MySQL 和 storage。不要手工删除 Milvus 向量；应通过后续受控重建索引接口保持 MySQL 与 Milvus 一致。

单端口运行使用 `start_production.ps1`，浏览器访问 `http://127.0.0.1:8000`。公网部署前必须配置 HTTPS、正式随机 `SECRET_KEY`、强数据库密码、防火墙和定期备份。

## 9. 新版课程入口、删除与收藏

进入作业中心、课堂运营、学情分析或教师学习报告后，先从课程卡片选择课程，再进入课程内容；顶部导航会显示当前位置。学生可反复提交同一作业。备课黄色收藏只改变状态，页面顶部“★ 收藏夹”才进入收藏页。桌面端左侧任务栏固定，不随正文滚动。

## 10. 协作模块与 Markdown 预览

协作者功能放在根目录 `plugins/`，由开发者审核后通过稳定适配层组合进现有业务，不需要管理员选择启用。当前 `plugins/spider` 同时用于知识库抓取和答疑网络补充。开发规则见根目录 `plugins.md`。

生成备课内容后会自动进入独立 Markdown 预览页；从历史点击“预览”也进入该页面。若从收藏页点击预览，顶部导航额外显示“收藏”，返回按钮也回到收藏页；仅仅把文件设为收藏不会改变从普通历史进入时的导航。预览显示渲染后的标题、列表、代码、引用和表格，下载按钮仍保存原始 `.md` 文件。

## 11. 模型启动预热

启动后端时会先加载 Ollama 对话模型、Embedding 模型和已配置的本地 BGE 重排模型，完成后才接受请求，因此首次备课、答疑或检索不再临时加载权重。预热可能使首次启动时间变长并占用内存/显存。系统不会自动下载缺失模型；管理员可从 `/health/ready` 查看预热结果。

知识库检索只展示通过相关性、内容长度和来源多样性筛选的片段；若没有片段达到要求，会明确提示未找到合格结果。

# 2026-07-15 本地启动与部署详细指南

## 依赖清单

| 环境/服务 | 版本/说明 | 用途 |
|-----------|-----------|------|
| Python | 3.11+（推荐 Conda 虚拟环境） | 后端运行环境 |
| MySQL | 8.0+，可用 Docker 部署 | 业务数据库 |
| Milvus | 2.3+，可用 Docker Compose 部署 | 向量召回 |
| 模型服务 | Ollama 本地服务 或 兼容 OpenAI API 的在线服务 | LLM / Embedding |
| BGE Reranker | 本地模型目录路径 | 重排序 |
| Node.js | 24 LTS 或更高 | 前端构建（项目已内置便携 Node） |
| pnpm | 9+ | 前端包管理（项目已内置便携 pnpm） |

模型服务支持 `ollama` 和 `openai_compatible` 两种 provider；`openai_compatible` 可覆盖 OpenAI、DeepSeek、阿里云百炼、智谱 AI 等。

## 首次部署步骤

### 1. 复制环境变量

```powershell
cd <project_root>
copy .env.example .env
```

重点配置：

- `MYSQL_PASSWORD`：与创建 MySQL 容器时一致。
- `RERANKER_MODEL_PATH`：指向本地 `bge-reranker-v2-m3` 目录。
- `LLM_*` / `EMBEDDING_*`：选择模型服务 provider，详见下方“模型服务配置”。

### 2. 启动 MySQL

首次使用 Docker：

```powershell
docker run -d `
  --name edu-mysql `
  -p 3306:3306 `
  -e MYSQL_ROOT_PASSWORD=root_change_me `
  -e MYSQL_DATABASE=ai_education `
  -e MYSQL_USER=ai_education_app `
  -e MYSQL_PASSWORD=change_me `
  -v "D:\Docker\mysql:/var/lib/mysql" `
  mysql:8.4 `
  --character-set-server=utf8mb4 `
  --collation-server=utf8mb4_0900_ai_ci
```

后续重启：

```powershell
docker start edu-mysql
```

### 3. 启动 Milvus

若使用 Docker Compose，参考 Milvus 官方文档启动 `etcd`、`minio`、`standalone` 三个服务。日常重启：

```powershell
docker start milvus-etcd milvus-minio milvus-standalone
```

等待 10~20 秒让 Milvus 初始化完成。

### 4. 安装 Python 依赖

```powershell
conda activate program-hd
cd <project_root>
pip install fastapi uvicorn[standard] sqlalchemy alembic pydantic pydantic-settings pymysql python-multipart httpx pymilvus pytest pytest-cov ruff
```

> 项目使用 `pyproject.toml` 描述依赖，也可在解决构建后端警告后使用 `pip install -e ".[dev]"`。

### 5. 执行数据库迁移

```powershell
cd <project_root>\backend
alembic upgrade head
```

### 6. 安装前端依赖

项目已内置便携 Node.js 24.18.0 和 pnpm 11.7.0，普通终端中没有全局 `node/npm/pnpm` 不影响启动。进入 `frontend` 目录后执行：

```powershell
cd <project_root>\frontend
..\bin\pnpm.cmd install
```

### 7. 启动后端

```powershell
cd <project_root>
powershell -ExecutionPolicy Bypass -File .\start_backend.ps1
```

或手动：

```powershell
cd <project_root>\backend
python -m uvicorn app.main:app --reload --reload-dir backend --app-dir backend
```

### 8. 启动前端

```powershell
cd <project_root>
powershell -ExecutionPolicy Bypass -File .\start_frontend.ps1
```

或手动：

```powershell
cd <project_root>\frontend
..\bin\pnpm.cmd exec vite --host 127.0.0.1
```

> Windows 上 Vite 可能默认监听 IPv6（`::1`），导致 `127.0.0.1` 访问不到，加 `--host 127.0.0.1` 可强制 IPv4。

## 模型服务配置


### 注意事项

- **Embedding 维度必须一致**：`EMBEDDING_DIMENSION` 要与所选 embedding 模型实际维度一致，且 Milvus collection 的维度也要匹配。若切换了 embedding 模型，通常需要重新创建 Milvus collection 或重新入库文档。
- **JSON mode 行为差异**：不同厂商对 `response_format: {"type": "json_object"}` 的支持程度不同。若出现 JSON 解析失败，可尝试换用更明确支持 JSON 输出的模型（如 qwen-max、glm-4、gpt-4o 等）。
- **温度参数**：部分厂商（如 Kimi `kimi-for-coding`）仅接受 `temperature=1.0`，因此 OpenAI 兼容 provider 默认不发送该字段，由服务商决定温度；需要固定温度时可在“模型服务”页面或 `.env` 中设置 `LLM_TEMPERATURE`。
- 管理员也可在运行后通过“模型服务”页面修改并加密保存配置；`.env` 中的值用于首次启动时的默认值。

## 常见问题补充

### Docker Hub 拉取镜像失败

在 Docker Desktop 设置中添加国内镜像源，例如清华镜像：

```json
{
  "registry-mirrors": ["https://mirrors.tuna.tsinghua.edu.cn"]
}
```

然后重启 Docker Desktop。

### `alembic upgrade head` 报 `Duplicate column name`

Code1 的迁移脚本已做幂等处理（先检查列/表是否存在），通常直接重新执行即可：

```powershell
alembic upgrade head
```

### 前端 `pnpm install` 提示 esbuild 构建脚本被忽略

确保 `frontend/pnpm-workspace.yaml` 包含：

```yaml
packages:
  - "."

onlyBuiltDependencies:
  - esbuild
```

然后重新 `pnpm install`。

### 前端能启动但 `127.0.0.1:5173` 访问不了

Vite 可能监听在 IPv6 的 `::1`。启动时加 `--host 127.0.0.1`：

```powershell
..\bin\pnpm.cmd exec vite --host 127.0.0.1
```

### `/health/ready` 返回 503

查看 `checks` 中哪个服务失败：

- **mysql**：检查 MySQL 容器是否启动、`.env` 账号密码是否正确。
- **models**：检查对应 provider 的地址、API Key、模型名是否配置正确；Ollama 需确认模型已拉取。
- **milvus**：检查三个 Milvus 容器是否都启动并初始化完成。

### 切换模型后向量检索异常

Embedding 模型变更后，旧文档的向量维度与新查询不一致。解决：

1. 清空 Milvus collection 中的旧数据（或删除后重建 collection）。
2. 在知识库中重新上传/入库文档。

### 模型输出 JSON 解析失败

- 优先使用明确支持 JSON mode 的模型（如 qwen-max、glm-4、gpt-4o）。
- 检查 `.env` 中 `LLM_MODEL` 是否正确。
- 在“模型服务”页面切换 provider 后需要重启后端。
